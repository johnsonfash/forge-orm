Started 2026-11-23T10:22:04.878Z. Seed: 1000 users, 10000 posts, 50000 comments, 50 tags, 1000 places. 10 measured iterations after 2 warm-up.

Server features: geo=true, fts=true, tx=true, json=true, geoMode=fallback

- geo uses forge's fallback mode (no SpatiaLite): JSON column, bbox prefilter + Haversine

Cells read `median / p95 ms (vs raw) · round trips`. Round trips are counted at the driver for every engine.

## Not run

- `json_prefs` prisma: Prisma has no JSON path filter on SQLite
- `json_meta` prisma: Prisma has no JSON path filter on SQLite
- `fts` prisma: Prisma has no full-text filter on SQLite
- `geo_near` prisma: Prisma has no geo filters; users drop to $queryRaw
- `geo_near` drizzle: Drizzle has no geo operators; it would be the same hand-written SQL as raw
- `geo_near` kysely: Kysely has no geo operators; it would be the same hand-written SQL as raw
- `geo_near` knex: Knex has no geo operators; it would be the same hand-written SQL as raw
- `stream` prisma: Prisma has no streaming read; findMany materialises the result
- `stream` drizzle: Drizzle's better-sqlite3 driver has no row iterator
- `json_fts_rel` prisma: Prisma has no full-text or JSON path filter on SQLite

```sql

```

```sql
SELECT id, email, name, role, active, created_at, prefs FROM users WHERE id = ?
```

### `filter_offset`

users role=USER AND active AND created_at in range, ORDER BY created_at DESC, id; OFFSET 20 (2 on tiny seeds) LIMIT 20

**forge** (1 round trip)

```sql
SELECT "users"."id", "users"."email", "users"."name", "users"."role", "users"."active", "users"."created_at", "users"."prefs" FROM "users" WHERE ("users"."role" = ? AND "users"."active" = ? AND "users"."created_at" >= ? AND "users"."created_at" < ?) ORDER BY "users"."created_at" DESC, "users"."id" ASC LIMIT 20 OFFSET 20
```

**raw** (1 round trip)

```sql
SELECT id, email, name, role, active, created_at, prefs FROM users WHERE role = ? AND active = ? AND created_at >= ? AND created_at < ? ORDER BY created_at DESC, id ASC LIMIT 20 OFFSET 20
```
